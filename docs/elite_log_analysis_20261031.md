**代码中会放大预测误差的环节。**

1. 精英排序混用真实准确率和 LLM 预测准确率。低估的新架构需要先通过生存选择，才可能获得真实查询；查询又只按预测分数选当前未测成员。低估会同时影响入选和评估机会。[选择与查询代码](/Users/gemaymini/Project/LLM-NAS/src/llm_enas_pkb/evolution.py:189)。
2. `fitness.setdefault(a, float(p))` 不仅保护已测真值，还永久保留未测架构的首次预测。同一结构在后续获得新预测时，旧低估可能仍然生效。这是已有行为，不是本次新增精英引入。[缓存更新代码](/Users/gemaymini/Project/LLM-NAS/src/llm_enas_pkb/evolution.py:187)。
3. 真值查询发生在下一代选择之后，纠正后不重新选择。当代预测过高的精英可能占用一代槽位。例如 CIFAR-10 seed1416360368 的 `[1,1,1,3,4,1]` 预测 89.90%，查真值为 74.60%，仍在当代下一种群第 3 位，下一代才退出精英。[预测](/Users/gemaymini/Project/LLM-NAS/logs/cifar10-elite-20/search_cifar10_DeepSeek-V4-Pro-0813_it30_pop20_seed1416360368_20261031-204913.log:78)；[查询后种群](/Users/gemaymini/Project/LLM-NAS/logs/cifar10-elite-20/search_cifar10_DeepSeek-V4-Pro-0813_it30_pop20_seed1416360368_20261031-204913.log:100)。

但“假精英长期占满名额”不受日志支持：CIFAR-10 的 660 次未测精英槽中 637 次当代即查询，CIFAR-100 的 651 次中 633 次当代即查询，约 97%。精英选择排名经重建也正确，历史最佳已测架构每代均保留，预算没有浪费。
