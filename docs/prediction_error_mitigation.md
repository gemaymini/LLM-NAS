# 预测误差传播的处理

本次修改将搜索顺序调整为：生成子代 → 选择 PKB → 更新预测 → 合并候选池查询真值 → 最终生存选择 → 记录日志 → 更新种群。

## 预测缓存

- `archive` 只保存已经查询的真实验证准确率。
- `fitness` 对已测架构始终使用真值，对未测架构使用最新可用预测。
- 每次获得新预测，覆盖未测架构的旧预测，并更新 `prediction_generations`。
- 默认仍只预测子代；未重新出现的未测父代保留旧预测，并在日志中显示预测代数。
- 可启用 `--refresh-parent-predictions`，将未测父代与子代去重后放入同一批预测。每代仍是一个预测批次，但 token 数可能增加；API 重试机制保持原样。
- 已测架构若作为子代获得新预测，原始预测仍可见于子代日志，但不会覆盖真值。

## 查询分配

查询对象来自去重后的父代与子代全集，排除 `archive` 中已有架构，不要求先进入下一代。

当代可用名额为剩余预算除以剩余代数、向上取整，再限制为当前未测候选数。初始化查询计入总预算；配置预算不足以覆盖初始化时直接报错。未消耗预算滚动到后续代，候选耗尽时允许最终实际查询数小于预算。

设初始化后已经完成 `Q` 次查询，其中 `E` 次为探索查询，当代实际可查询 `n` 个候选，探索比例为 `r`：

```text
本代探索名额 = floor((Q + n) * r) - E
本代利用名额 = n - 本代探索名额
```

实现会修正浮点乘法在整数边界附近的舍入误差，并将名额限制到 `[0, n]`。计算以实际可查询数为准，空候选池不消耗预算或配额。

利用名额选预测分数最高的候选；探索名额从剩余候选中均匀、无放回随机抽取。默认 `r=1/3`，单查询代的分配是“利用、利用、探索”循环。若仅有一次或两次初始化后查询，默认比例下可以没有探索查询；需要立即探索可提高比例。

默认配置为初始化 20、总预算 100、迭代 30 代。若实际用满额外 80 次查询，其中 26 次为探索，54 次为利用。随机抽样使用搜索的种子 RNG，同一种子加相同预测结果可复现；在线 LLM 输出本身不保证确定性。

## 生存选择

查询结果写入 `archive` 和 `fitness` 后，只执行一次最终选择：

1. 当前合并池中的已测架构按真值排序，保留最多 `floor(population_size * elite_ratio)` 个精英。
2. 其余名额从所有非精英候选中做二元锦标赛，已测用真值，未测用最新预测。
3. 已测架构不足时，将未用精英名额交给锦标赛。历史 archive 中已经离开候选池的架构不自动复活。
4. 种群保持去重；候选不足时不重复填充。

这使查真值后被纠正的高估架构当代就失去不应获得的精英保护；低估架构也能通过探索查询获得真实竞争机会。未测架构仍可通过锦标赛生存，预测误差仍可能影响这部分结果。

## 配置

| 配置 | 默认值 | 命令行 | 环境变量 |
|---|---|---|---|
| 精英上限比例 | `0.25` | `--elite-ratio` | `LLMENAS_ELITE_RATIO` |
| 初始化后查询的探索比例 | `1/3` | `--query-explore-ratio` | `LLMENAS_QUERY_EXPLORE_RATIO` |
| 同批刷新未测父代预测 | `False` | `--refresh-parent-predictions` / `--no-refresh-parent-predictions` | `LLMENAS_REFRESH_PARENT_PREDICTIONS` |

两个比例必须为 `[0, 1]` 内的有限数。`query_explore_ratio=0` 只关闭随机查询，不恢复旧的“先选择后查询”；`elite_ratio=0` 只关闭精英保护。`elite_ratio=1` 在已测候选充足时完全按真值选择，否则仍用锦标赛填充。

## 日志与返回值

- 日志头记录策略、探索比例和父代刷新开关。
- `Population` 保存本代开始时的父代成员、分数、GT/pred 标签和预测代数；`Next population` 使用查询后的结果。
- PKB 的 archive 数量按构建提示时的快照记录，避免混入本代随后新增的查询。
- 每次查询记录架构、原因、查询前预测、预测代数、真值和带符号误差 `prediction - truth`；正数表示高估。文本日志同时标明是否最终生存。
- 单列最终真值精英及其真值；被查询但未入选是正常结果。
- 父代保留数和子代入选数按架构集合统计，另列交集数与真正新增子代数。满足 `父代保留 + 子代入选 - 交集 = 下一代大小`。
- `mean_pop_valid` 继续表示最终下一代中已测成员的平均真值，不是整个种群的真实均值；无已测成员时为 NaN。
- `history` 保留原字段，新增 `query_records`、`elites`、`parents_retained`、`offspring_selected`、`overlap_selected`、`new_offspring_selected`，支持后续分析。

## 验证和实验边界

回归测试覆盖预测更新/真值保护、低估救回、高估当代纠正、未测父代查询、累计探索名额、预算滚动、不重复查询、比例边界、配置优先级、真实日志输出及跨代父子种群衔接。

```bash
uv run python -m unittest discover -s tests -v
```

这些测试验证执行机制，不证明真实搜索效果提升。效果实验建议分别比较旧策略、仅缓存更新、查询前移加探索、加入真值精英，以及可选的父代预测刷新。前几个阶段需要对应代码版本，不应将本版本的比例开关误当作全部旧策略的复现开关。

对照时固定初始种群、种子组、验证查询预算、模型与提示配置，比较 best-valid 随累计查询数的曲线和多次运行的分布。父代刷新实验另记录 LLM token/调用成本。避免仅用同一组预测重放结果宣称实际搜索收益，因为策略改变后，种群、PKB 和后续预测输入都会变化。
