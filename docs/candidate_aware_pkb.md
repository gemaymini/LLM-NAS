# 面向待预测候选的 PKB

默认采用 20 个示例：6 个全局参考，14 个逐步增加候选覆盖的参考。每个候选的覆盖由最近两个不同架构示例的相似度平均值衡量。PKB 仍只向 LLM 提供架构编码和真实验证准确率，不包含历史预测值、高估或低估案例。

## 集合与时序

- `A`：预测开始前已经查询真值的 archive。
- `Q`：本次送入预测器的架构中，去重且排除 `A` 后的未测候选。
- `S`：已经选中的 PKB 架构。

默认预测子代，因此 `Q` 是其中的未测架构；开启 `--refresh-parent-predictions` 时，同时纳入未测父代。已测子代仍遵循现有预测接口，但不参与覆盖权重，也不能覆盖已知真值。

先确定实际预测批次，再选择 PKB、调用预测器，最后才进行本代真值查询。本代新查询标签不能回流到本代的 PKB。

## 相似度与目标

采用六个对应边位置上操作 ID 相同的比例：

```text
s(a, q) = 相同操作位置数 / 6
C_k(S, Q) = mean over q of (sum of the k largest s(a, q), a in S) / k
```

默认 `k=2`。参考少于 k 个时，缺项为零，分母仍然为 k；不会让只有一个参考的 PKB 冒充已有两个参考。每个不同候选权重相同，重复候选不增加权重。

## 选择步骤

1. 从整个 archive 计算原有的性能—多样性综合分数与拥挤距离。
2. 将原 `k_perf:k_div` 的相对配额缩放到全局名额。默认 `10:12` 在 6 个名额下四舍五入为 `3:3`；两路都启用且全局名额至少为 2 时，每路至少 1 个。两组去重后不足的部分按原综合分数补齐。
3. 以全局参考为初始 `S`，反复选择使 `C_k(S ∪ {a}, Q) - C_k(S, Q)` 最大的未选架构。
4. 增益相同时，优先选择与当前 `S` 的最大相似度更低的架构，再比较原综合分数，最后按 archive 索引稳定排序。
5. 若所有增益均为零，则按与 `Q` 的平均相似度、非重复程度、原综合分数、archive 索引依次补齐。

实现使用 0～6 的整数匹配数计算增益排名，避免浮点求和舍入使数学上相同的增益排序不一致。没有增加随机抽样。

全局参考数上限为 `min(pkb_global_size, selected_size, archive_size)`。archive 不足时全部保留，不重复填充；没有未知候选时退回原策略。空 archive 的选择结果为空。PKB 大小、邻居数必须为正整数，全局名额及两路候选数必须为非负整数。

## 配置与使用

| 配置 | 默认值 | CLI | 环境变量 |
|---|---|---|---|
| 策略 | `candidate_aware` | `--pkb-strategy` | `LLMENAS_PKB_STRATEGY` |
| PKB 大小 | `20` | `--selected-size` | `LLMENAS_SELECTED_SIZE` |
| 全局参考名额 | `6` | `--pkb-global-size` | `LLMENAS_PKB_GLOBAL_SIZE` |
| 每候选的覆盖邻居数 | `2` | `--pkb-coverage-neighbors` | `LLMENAS_PKB_COVERAGE_NEIGHBORS` |

```bash
# 默认候选感知策略
uv run llm-enas-pkb --seed 0

# 显式指定本版设置
uv run llm-enas-pkb --seed 0 --pkb-strategy candidate_aware \
  --selected-size 20 --pkb-global-size 6 --pkb-coverage-neighbors 2

# 原 PKB 选择策略作为对照，仍使用当前查询和生存选择流程
uv run llm-enas-pkb --seed 0 --pkb-strategy original
```

`original` 保留原 `select_pkb` 的样本选择行为，不表示恢复整个项目的历史版本。两种策略使用相同的编码、提示格式和预测接口。CLI 显式参数覆盖环境设置。

## 日志和返回信息

日志头记录策略、总大小、全局大小与邻居数。每个 PKB 条目的 `source` 为：

- `global`：全局性能—多样性参考；
- `coverage`：通过正覆盖增益加入；
- `relevance_fill`：覆盖增益饱和后补齐；
- `original`：原策略或没有未知候选时的回退策略。

默认的 14 个局部名额包括 `coverage` 和 `relevance_fill` 两种来源。日志同时记录实际选择模式、未知候选数、全局参考阶段与最终 PKB 的覆盖结果：

- `mean_nearest` / `min_nearest`：候选最近参考相似度的平均值与最小值；
- `mean_topk` / `min_topk`：候选最近 k 个参考平均相似度的平均值与最小值；
- 每个候选的编码、最近参考相似度、top-k 平均相似度。

无未知候选时这些汇总值为 `None`，日志不输出虚假的数字。结构化信息放在 `history[generation]["pkb"]`，包含选中架构、来源、实际模式、最终覆盖和全局阶段覆盖。

## 验证与限制

测试覆盖默认 6+14 配额、全局两路配额缩放、候选改变引起的选择变化、不同结构群的覆盖、每步真实目标增益最大化、重复/已测候选不加权、操作 ID 重标号不变性、零增益补齐、小 archive、原策略回退、配置覆盖、预测前真值边界以及真实日志输出。

新策略不额外查询基准真值，不增加每代预测批次数。每个候选有两个近邻是优化目标，不是保证；archive 本身没有近似结构时无法凭选择创造参考。相似结构也可能具有不同性能，覆盖率不应解释为置信度。

效果评估应固定历史 archive 与待预测批次，比较原选择、独立相关性排序、集合覆盖选择的预测误差与排名质量，再在相同种子组和真值预算下比较完整搜索。独立相关性排序仅作为后续消融建议，本版内置策略是 `original` 和 `candidate_aware`。目前的功能测试不证明真实 LLM 预测准确率提升。
