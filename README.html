LLM-ENAS-PKB — Regression surrogate on NAS-Bench-201

A faithful re-implementation of the regression-based LLM surrogate model from

Fang, W., Xue, Y., Yuan, L., Hasan, M. K., Aurangzeb, K. (2026). Large language model assisted evolutionary neural architecture search with population knowledge base enhancement. Information Sciences, 735, 123110. (official code)

The paper replaces the expert-designed surrogate model in evolutionary NAS with a large language model (DeepSeek-R1). This repository implements the regression variant on NAS-Bench-201 (d = 30 input dimension, see Table 1 of the paper), driven by the DeepSeek official API.

Environment (uv)

uv sync                 # create .venv + install deps (incl. torch, nas-bench-201)
export DEEPSEEK_API_KEY=sk-...   # or put it in .env
uv run llm-enas-pkb --dataset cifar10 --iterations 30

Python is managed by uv (requires-python >=3.10,<3.13); no system Python is used.

DeepSeek API

  • Endpoint: https://api.deepseek.com/chat/completions (OpenAI-compatible).
  • Model: deepseek-v4-pro (DeepSeek-V4 reasoning model). The paper used deepseek-reasoner (DeepSeek-R1), which the official API has since retired. Set LLMENAS_MODEL=deepseek-flash to use the faster V4.1-Flash model instead.
  • Auth: DEEPSEEK_API_KEY (or LLMENAS_API_KEY_ENV to point at another variable).

Note: the paper reports a repetition_penalty of 1.8 (a HuggingFace parameter); the OpenAI-compatible API has no direct equivalent, so frequency_penalty (default 0.0) is the closest analogue and is exposed via LLMENAS_FREQUENCY_PENALTY.

Prompt logging

Every prompt sent to the API and the text the model returns are appended in real time (one flush per exchange) to llm_prompts.log in the working directory, so you can inspect exactly what the model saw and produced:

tail -f llm_prompts.log   # watch entries land while a run is in progress

Disable it with LLMENAS_PROMPT_LOG_PATH="" (or --prompt-log-path ""), or redirect it with LLMENAS_PROMPT_LOG_PATH=/tmp/prompts.log. Failed writes are warned and ignored, so a missing/invalid path never aborts the run.

NAS-Bench-201 data

nas-bench-201 (import name nas_201_api) is installed from PyPI. The benchmark archive (NAS-Bench-201-v1_1-096897.pth, ~4.7 GB) must be obtained from the official repo (Google Drive; automated download is frequently blocked by Drive's quota limit, so manual download is recommended):

# Put the file at either of these locations (auto-detected), or pass --data-path.
data/NAS-Bench-201-v1_1-096897.pth          # project-local (recommended)
~/.torch/NAS-Bench-201-v1_1-096897.pth      # legacy TORCH_HOME location
uv run llm-enas-pkb --data-path /abs/path/NAS-Bench-201-v1_1-096897.pth

A best-effort auto-download (via gdown) is attempted as a last resort (scripts/download_data.py).

Running

# Full evolution (regression surrogate, 30 generations, 100-query budget)
uv run llm-enas-pkb --dataset cifar10 --seed 0

# Quick smoke test without calling the API (deterministic pseudo-LLM)
uv run llm-enas-pkb --offline --iterations 3

# Predict a couple of candidate architectures from a small labelled archive
uv run python - <<'PY'
from llm_enas_pkb import Config
from llm_enas_pkb.nasbench201 import NASBench201
from llm_enas_pkb.predictor import RegressionPredictor

cfg = Config(offline=True)          # deterministic pseudo-LLM (no API key)
nb = NASBench201(cfg)
pred = RegressionPredictor(cfg)

pkb = [(0, 1, 2, 3, 4, 1), (4, 3, 2, 1, 0, 1), (1, 1, 1, 1, 1, 1)]
pkb_vals = [nb.valid_acc(a) for a in pkb]   # ground-truth labels
candidates = [(2, 2, 2, 2, 2, 2), (0, 0, 0, 0, 0, 0)]
print(pred.predict_archs(candidates, pkb, pkb_vals))
PY
